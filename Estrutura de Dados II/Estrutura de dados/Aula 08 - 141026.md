## Tabela hash(dispersão)

hash -> registros armazenados em uma tabela são endereçamento a partir de uma transformação aritimética sobre a chave de pesquisa. Econtrar os endereços a partir desses hashs.

As distribuição das chaves na tabela devem ser uniformes. Não devem existir muitas chaves no mesmo endereço de memória

Objetivo: ter eficiência média de 0(1)

#### Método de pesquisa
- Computa o valor da função hash(função que transforma a chave da pesquisa em um endereço da tabela)
- Dado que duas ou mais chaves podem ser transformado em um mesmo endereço, é necessário existir um método pra lidar com colisões

#### Função hash
Deve receber um universo de chaves e retornar um valor numérico.

```C
int calcular_hash(const char* chave, int tamanho_tabela) {
    int soma = 0;
    
    // Percorre cada caractere da string
    for (int i = 0; chave[i] != '\0'; i++) {
        soma += chave[i]; // Soma o valor da tabela ASCII do caractere
    }
    
    // Retorna o resto da divisão para garantir que o índice caiba no array
    return soma % tamanho_tabela;
}
```

##### Endereçamento direto
- Quando o universo de chave é pequeno, podemos alocar uma tabela com uma posição pra cada chave, ou seja, | T | = | U |
- Então cada posição da tabela, que pode se rimplementada como um vetor, representa uma chave de U e armazena um elemento ou um ponteiro para o elemento

```C
// Isso é bem burro de se fazer, apenas a nível de visualização
int hash_direto(int chave) {
    return chave;
}
```

Mas nem sempre U é pequeno, em universo de chaves muitos grande é necessário alocar uma grande quantidade de memória para tabela mesmo que ela sequer esteja cheia.

Logo a solução é usar uma função hash em h para mapear as chaves em inteiros dentro do intervalo ```[0, ... m -1]```

##### O que faz uma função hash ser de boa qualidade?
- sastifaz o hash uniforme simples
	- Cada chhave tem igual probabilidade de efetuar o hash para qualquer das m posições, não importando a posição para onde foi feito o hash de qualquer outra chave
- Em geral, não é possível verificar essa condição

Uma boa tática é derivar a tabela hash de um modo supostamente independente de quaisquer padrões que possam existir nos dados

#### Como evitar colisões
Isso depende de como a função mapeia as chaves na tabela. Exemplo: um numero primo não próximo de 2 tende a distribuir melhor as chaves na tabela. Mas como o | U | > posições na tabela, a função apenas minimiza o numero de colisões

As colisões remanescente devem ser tratada de forma algoritímica, aplicando tecnicas de encadeamento ou endereçamento aberto

- ##### Encadeamento
	-  construir uma lista encadeada pra cada endereço
		- Houve colisão? adiciona na lista
		- Assim todas as chaves com mesmo endereço são armazenadas em uma lista
##### Encadeamento interior
Em algumas aplicações não é desejavél uma estrutura exterior. Assim ruusamos listas encadeada, desde que estas compartilhem o mesmo espaço de memŕoai que a tabela
