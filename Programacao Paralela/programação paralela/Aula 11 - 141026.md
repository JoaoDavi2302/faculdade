Fase onde a gente, finalmente, vai codar

deve-se levar em conta a arquitetura de hardware disponível

Já existem padrões clássicos que podem ser aplicados em diversas situações, a gente pode adaptar essas estruturas

- Fork-join
- MAP
- Stencil
- Reduction

### Fork-join
- Permite que o fliuxo de controle seja dividido em múltiplos fluxos. Uma thread será dividida em várias pra ser executado em paralelo
- No final da operação elas serão unidas em uma unica thread sequencial que executará o restante do código sequenciado
- Muito utilizado com openMP
### Map
- Aplicar uma mesma função sobre o mesmo conjunto de dados
	- Se aplica a paralelização de laços nos casos onde se pode aplicar uma função independente a todo o conjunto de elementos
- Lembra muito o método .map do javascript, basicamente aplica uma função ao conjunto dentro do array e gera novos dados

### Stencil
- É uma generalização do MAP, onde a função é aplicada sobre um conjunto de vizinhos definidos a partir de um conjunto offset relativo a cada ponto do conjunto

### Reduction
- Se trata de reduzir um conjunto de dados a um unico dado. Se aplica uma operação que simplifica a estrutura de dados.
	- é como somar todos os valores de uma lista e atribuir a uma variavel

### Testes de correção
O objetivo não é abordar técncias ou formalismo de areas de teste de software. A ideia é que os resultados se assemelhem os resultados com o programa sequencial aumentando seu desempenho

Basicamente
Saida sequencial = saida paralela, desde que desempenho maior.

O cuidado maior é com programas de natureza não determinística, todavia o código paralelo nesse caso deve possuir o mesmo padrão não determinístico

### Analise de desempenho
Deve comprovar que a transformação de sequencial para paralelo está gerando impacto em seu desempenho.
##### Granaulação
Mede se o código está realizando mais comunicação ou mais computação. é arazão entre tempo de comunicação e de computação
- Fina: frequencia de comunicação é maior que o processamento. Tende a diminuir o desempenho uma vez que necessita um alto custo de sincronização
- Grossa: processamento maior comunicação, pode melhorar o desempenho devido ao fato que o a sincronização vai diminuir

##### Critério de analise
- Tempo de execução -> mais direta que temos
	- Texec = Tcomp + Tcomn + Tocio
		- Texec: tempo de execução
		- Tcompo: tempo de computação
		- Tcomn: tempo de comunicação
		- Tocio: tempo ocioso
- Speedup
	- razão entre tempo de execução em apenas um núcleo em relação com o tempo de execução em multiplos nucleos. basicamente: código sequencial / código paralelo
	- unicade unidimensional
- Desempenho
	- Determina o quanto os processadores estão sendo utilizados
	- Eficiência x 100%
- Eficiência
	- Determina a relação entre speedup obtido e o numero de processadores necessários para obterlo
	- Speedup / N de processadores

##### Calculos teóricos
existem forma de calcular o speedup de forma teórica antes de executar a aplicação utilizando-se de duas "Leis"
###### Lei de amdahl
- Usada para determinar o speedup teórico de uma aplicação
- Limitado pelo tempo necessário para executar a fração sequencial desse programa
Basicamente determina oq pode e oq não pode ser paralelizado. Divide o código em duas categorias
 - Fraççao serial: trechos que não pode ser paralelizado
 - Fração paralela: O que pode ser paralelizado
A fração serial é limitada em função da analise de dependência de dados

###### Lei de Gustafson
A computação envolvendo um conjunto arbitrariamente grande de dados de entrada pode ser eficientemente paralelizada. 

Não há variação no tamanho do problema. Nessa analise fixa-se o tamanho do problema e varia-se o numero de unidade de processamento

### Metodologia PCAM
é util sempre ter disponivel a versão sequencial do código para indentificar gargalos. Indentificar os trechos que exisgem maior computação 
- Determinar funções que podesem ser executadas em paralelos(particionar ou decompor)
- Eliminar dependências e condições de corridas
- Resultados paralelos deverão ser iguais aos seriais

PCAM - Particionmento, Comunicação, Agregação, Mapeamento
 - Particionamento
	 - Decomposição de dominios/dados
	 - Decomposição funcional -> não temos conhecimento da quantidade de dados. A ideia é decompor em funções independentes
- Comunicação
	- Determinar o padrão de comunicação entre as tarefas
- Agregação
	- Combinar as tarefas de forma a se estabelecer a comunicação, se necessáiro, visando reduzir custos
- Mapeamento
	- Alocar tarefas ás unidades de processamento
