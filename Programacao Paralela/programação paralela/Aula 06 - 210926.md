## Classificação de duncan
Surgiu com a necessidade de acomodar arquiteturas que não se encaixavam na flynn. Surgiu na decada de 1990

- Excluiu os tipos de paralelismo de baixo nivel
	-  Pipeline dos estágios de execução a nivel de instrução
	-  Operaçõs realizadas diretamente pela arquitetura

Dividiu entre **Arquiteturas síncronas** e **Arquiteturas assíncronas**

##### Arquitetura síncrona
Utilizam mecanismo de sincronização como relógios globais, unidades de controle centralizadas ou unidade de controle vetoriais

quase como varios CPU sendo gerenciada pelo mesmo clock e pela mesma unidade de controle. A execução é coordenada e harmonica

- SIMD
- Processadores vetoriais
- Arquitetura sistonica

###### SIMD
- Uma única instrução operando sobre multiplos dados
- Essas arquiteturas possuem uma unidade de controle entralizada
- varias unidades de processamento

muito eficiẽncia quando se há a divisão efetiva dos dados

###### Processadores vetoriais
Possuem hardwares específicos para lidar com operações vetoriais. Evita laços de repetição para percorrer estruturas complexas

O calculo de cada reusltado não depende de resultado anteriores. sem dependencia de dados

###### Arquitetura sistólica
Transferência de dados de forma otimizada que permite fazer milhares de multipicações matematica ao mesmo tempo, o que forma a base de redes neurais.

A arquiteutra sistólica não consulta memória. as unidades de processamento são interligadas uma com as outras, os dados são empurrados de uma up para a outra em uma cadeia de unidades de processamento. fazem processamento tensorial
#### Arquiteturas assíncronas
caracterizam-se pelo controle descentralizado do hardware. Cada unidade pode executar uma instrução ou ser controlada por outra de forma independente

- Arquiteturas MIMD
- Paradigmas MIMD
###### Arquiteturas MIMD
Multiplas instruções em multiplos dados possibilitando um alto nivel de paralelismo. centralizado em uma parallismo de tarefas.

varias UP's que operam de maneiras diferentes

Arquitetura MIMD podem ser memória centralizada ou distribuída.
##### Paradigma MIMD
- MIMD/
- SIMD -> Hibrida
- Fluxo de dados(dataflow)
- Redução
###### Hibrida
Mistura de MIMD com SIMD. partes MIMD e partes SIMD constituindo a arquitetura

muito utilizado em processamento de imagens e sistemas especialistas

###### Fluxo de dados
Uma instrução é executada quando todos os seus operandos estão disponivies, ou seja, a instrução só é executada pela disponibilidade dos dados de entradas

Pode-se controolar pontos de sincronismo dentro de arquiteturas paralelas, pode ser importante existir essas barreiras de sincronismo para poder escrever ou ler dados no disco. Permite que algumas tarefas sejam sincronizadas em alguns pontos

###### Redução
implica que partes do códigos devem ser reduzido aos seus resultados em tempo de execução. 


### Tipos de comunicação
Dependedo da arquitetura utilizada na construção da memória muda-se o contexto da programação

- Memória compartilhada -> threads
- Memórias distribuídas -> tarefas

#### Memória Compartilhada
A comunicação entre as tarefas é realizada por meio de variaveis compartilhadas que podem ser mapeadas em **threads** ou **processos**

Nas threads o acesso é mais baixo complexidade e mais rápidade.

pode ser classificada em UMA E NUMA

##### UMA 
-  A memória utilizada nessas maquinas é global e tem a mesma distancia entre as UP's
-  O tempo de acesos é uniforme para todos
-  A memória principal é implementada como um unico bloco

Um dos problemas é a escalabilidade. O numero de processadores depende do tamanho da placa e o acesos de multipas UP's a uma unica memória é um problema. 

A solução encontrada foi implementar niveis de caches onde a cacha de nivel 3 é compartilhada entre as UP's sem que haja a necessidade de acesos ao barramento ou a memória principal.

No entando o uso dessas caches pode introduizir incosistencias de caches devido a problema de atualização de dados. Para isso s eutiliza algoritimos em hardware para manunteção de dados.

Usa-se muito a **técnica de snooping**
