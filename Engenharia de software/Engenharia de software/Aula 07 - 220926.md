## Engenharia de requisitos
- Concepção de um novo sistema -> declaração de um novo sistema
	- declarar oq ele faz e o que não faz a fim de delimitar um escopo e evitar um aumento descontrolado de requisitos
	- Declara-se
		- O problema de:
		- Afeta quem:
		- Cujo o impacto:
		- Uma boa solução seria:
	- Se resolve o problema a partir do seu impacto que é a causa do problema, assim eliminamos a recorrencia do problema.

#### Documento de abertura
- Se justifica e delimia o problema
- delimita claramente o escopo do projeto 
- define claramente o que não faz parte do escopo do projeto

#### Requisitos
- Fundamentaias para o projeto
- Grande impacto do desenvolvimento
- caracteristicas funcionais e técnicas do sistema

---
##### engenharia de requisito é o processo de
- Descobrir
- Analisar
- Documentar
- Verificar

	 documentar é diferente de validar. Documentar é o processo interno da equipe de fazer uma checagem dos requisitos

	 Validar é o processo de homologação com o cliente

Consiste em dois grupos **Desenvolvimento de requisitos** e **Gerência de requisitos**
- Desenvolvimento cria e interpreta os requisitos
- A gerência organiza, e verifica as mudanças de requisitos
---
## Classificação de requisitos
Requisitos podem ser do usuário ou do sistema.

- Requisitos do usuario => regra de negócio(funcional)
- Requisitos do sistema => aspecto técnico(não funcional)
